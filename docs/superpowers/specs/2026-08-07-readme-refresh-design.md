# QwenWorkGuide README 改写设计

## 目标

让第一次打开 GitHub 仓库的读者在 10 秒内看懂三件事：这是什么、它能帮自己解决什么问题、应该从哪里开始。首要读者是企业 AI 负责人和业务负责人，同时为普通办公用户保留明确的快速上手入口。

## 核心表达

README 以「问题切入 + 内容证明」为主线。开头先用通俗语言说明：AI 生成一份内容，不等于完成一项工作；这份开源指南关注如何把任务做成可检查、可复用、可管理的工作流。随后用已有章节、案例、模板和验收清单证明内容不是口号。

保留「从一句话，到可交付的工作系统」作为项目的品牌表达，但不让它单独承担解释项目的任务。

## 信息结构

README 按以下顺序组织：

1. 项目名称、一句话价值和在线阅读入口。
2. 「这份指南适合谁」，说明企业决策、团队落地和个人上手三类需求。
3. 「你能在这里找到什么」，用业务问题而不是抽象章节名组织内容。
4. 「按你的目标开始」，分别链接快速上手、案例、企业落地和完整蓝皮书。
5. 内容可信边界，简要说明事实、社区经验、来源和核验日期的处理方式。
6. 参与共创、安全提醒、本地开发与许可证。

Cloudflare Pages 部署说明从阅读主线移出，放入可折叠的「站点部署」区域，仍保留现有的准确配置。

## 文风与边界

- 使用短句和常用词，一段只表达一件事。
- 先说读者面临的问题，再说项目包含的内容。
- 不使用「革命性」「全面提效」等无法核验的宣传词，不承诺未经证明的业务效果。
- 不把社区方法写成官方结论，保留非官方声明、核验边界和隐私提醒。
- 中英文、数字、标点和链接排版遵循仓库现有的中文文档风格。

## 验收标准

- README 的前两屏能回答「这是什么」「适合谁」「能解决什么」。
- 新读者最多经过一次点击，即可进入快速上手、案例、企业落地或完整蓝皮书。
- 所有章节数量、案例数量、文件路径、命令和部署配置均与仓库当前状态一致。
- Markdown 标题不跳级，本地链接可解析，代码块标注语言类型。
- `npm run check` 通过，证明文档规则、测试和站点构建未受影响。

## 范围

本次只改写根目录 `README.md`。不调整蓝皮书正文、站点首页、导航、构建配置或案例数据；如果 README 与现有内容存在事实冲突，以仓库中可验证的现状为准。
