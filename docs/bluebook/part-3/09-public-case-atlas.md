## 怎么读案例

先看案例原来的麻烦，再看最后得到的产物；接着核对输入、复用步骤和验收条件，最后再看客户陈述、待核验项和权限边界。具名案例中的结果是客户材料中的陈述，32 个场景图谱是待核验公开场景线索，二者都不能替代你自己的基线和人工判断。

## 如何复用

1. 用自己的数据、规则、素材、权限和验收口径替换案例输入，不直接复制示例内容。
2. 先做低风险草稿或只读分析，记录人工修改、异常和返工，再决定是否扩大范围。
3. 客户材料中的结果不能直接照搬；产品、品牌、HR、财务或其他业务负责人应按场景人工确认最终结论和对外动作。

## 为什么重要

案例名称看起来具体，不等于来源可以逐条复核。R11 的访客页能展示候选名称和标签，但只暴露集合级的 `sheetId=hERWDMS`、`viewId=HdnvUtk` 以及集合级 Wiki 定位；卡片点击后 URL 不变，访客也不能通过“源数据”获得案例级记录 ID、卡片深链或稳定 URL。

这一区别决定了案例能否被引用、纠错和长期维护。若读者无法从正文回到某条原始记录，就无法确认名称与标签是否属于同一条记录，也无法判断链接失效、内容更新或归属变化。因此，集合级可见性只能产生待核验线索，不能直接形成公开案例成员。

## 发布门与核验方法

公开案例采用逐条发布门，不按集合页可见数量计算：

| 发布门 | 通过条件 | 未通过时的处理 |
|---|---|---|
| 案例身份 | 有案例级外部记录 ID，且不使用本书自建 ID 冒充外部 ID | 保持 pending |
| 来源定位 | 有案例级稳定深链，或在许可范围内保存公开快照及内容哈希 | 不进入公开计数 |
| 内容对应 | 名称、标签、来源定位和示例产物能够稳定对应到同一条记录 | 记录冲突并继续补证 |
| 发布边界 | 不包含未经许可的身份、客户结果或敏感信息 | 去标识化或停止发布 |
| 复核记录 | 保存核验日期、状态、局限和责任角色 | 不创建代表案例卡 |

结构化口径以 [案例来源映射](/bluebook/appendices/case-source-map) 为准：只有 `included_in_public_count` 为 `true` 的条目才进入公开数量和成员清单。证据卡、来源优先级与冲突处理沿用 [研究与证据链](/bluebook/part-3/08-research-evidence-chain)，不在本章另建一套判断标准。

## 企业行动

团队准备公开一个候选案例时，按以下顺序补证：

1. 由案例证据复核者取得案例级外部记录 ID 和稳定来源定位。
2. 逐项核对原始名称、原始标签、来源记录与示例产物的对应关系。
3. 记录访问日期、证据状态、适用范围和不能支持的结论；有冲突时先降级。
4. 只有在许可明确时才制作公开快照，并同时登记内容哈希；没有许可时不创建快照。
5. 复核公开内容中的身份、结果、敏感信息和传播文案，再把结构化状态改为可发布。
6. 重新生成附录并运行内容校验，让正文计数、成员清单和结构化数据保持一致。

## 边界与下一步

本章是截至 2026-08-01 的内容快照，不对 R11 集合页之外的内部记录作推断，也不把无法稳定定位的卡片内容转录为公开事实。公开数量会随补证、失效或撤回而变化，每次发布都必须重新运行同一发布门。
