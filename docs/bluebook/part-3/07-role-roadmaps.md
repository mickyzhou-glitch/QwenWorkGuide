# 岗位路线：用统一场景卡选择真实任务

## 30 秒结论

<span id="claim-role-scenario-card-01" data-claim-id="claim-role-scenario-card-01"></span>本书建议：岗位 AI 场景统一使用业务问题、角色、输入、当前步骤、交付物、验收、禁做动作、指标、风险、基线十个字段登记，先证明一个任务有效，再组合岗位工作流。

- 岗位名称不能代替具体业务问题。
- 指标必须与人工基线比较，并同时观察质量和风险。
- 场景评分、样本要求和阶段门只由第 10 章定义。

## 为什么重要

“给 HR 一个助手”或“为销售做智能体”无法直接验收。岗位范围太大，数据权限和后果也不一致；一个成功的材料整理任务不能证明人员决策、报价或发布动作可以自动化。

统一场景卡把岗位需求压缩成可比较的业务单元。企业 AI 负责人可以按真实输入、当前步骤和风险选择试点，业务负责人可以确认交付物和禁做动作，运营团队可以采集同口径基线。

## 方法或模型

场景卡的十个字段在所有岗位保持同义；下列五张卡是起步示例，不是固定最佳实践。

### HR：招聘周会状态整理

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 招聘周会前需要快速识别职位阻塞和缺失反馈 |
| 角色 | 招聘负责人、招聘专员、用人经理 |
| 输入 | 获授权的职位台账、面试反馈、入职准备清单和上周版本 |
| 当前步骤 | 导出、合并、追问缺失项、整理状态、准备周会 |
| 交付物 | 职位—阶段—阻塞—负责人—下一步的可编辑状态表 |
| 验收 | 每个状态可回到原始反馈；缺失项单列；责任人和截止时间明确 |
| 禁做动作 | 不自动录用、淘汰、评价候选人，不向无权限对象传播个人信息 |
| 指标 | 准备时长、反馈完整率、状态误配率、人工修改量 |
| 风险 | 候选人隐私、反馈偏见、同名误配、旧状态覆盖 |
| 基线 | 记录当前人工准备时间、缺失反馈、退回和修正样本 |

### 销售与商务：客户拜访准备与跟进

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 会前信息分散，会后行动和承诺容易遗漏 |
| 角色 | 客户经理、售前、销售负责人 |
| 输入 | 公开信息、获授权的 CRM 记录、历史沟通和产品资料 |
| 当前步骤 | 搜集、核对、形成提纲、记录会议、起草跟进 |
| 交付物 | 一页准备单、事实与待确认问题、邮件草稿、待写入清单 |
| 验收 | 事实标注来源和日期；承诺、报价、负责人和截止时间经过确认 |
| 禁做动作 | 不自动报价、承诺、发送或修改客户主记录 |
| 指标 | 准备时长、事实错误率、行动遗漏率、CRM 建议采纳率 |
| 风险 | 客户信息越权、陈旧信息、虚构承诺、错误收件人 |
| 基线 | 采集现有准备用时、会后遗漏、退信和记录修正情况 |

### 产品与项目：项目风险台账

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 需求、周会和缺陷中的变化无法及时汇总为决策请求 |
| 角色 | 产品经理、项目经理、研发负责人 |
| 输入 | 需求文档、项目计划、周会记录、缺陷和变更日志 |
| 当前步骤 | 对齐版本、提取变化、判断影响、分配责任、请求决策 |
| 交付物 | 风险台账、变更摘要、待决事项和版本发布说明草稿 |
| 验收 | 风险有证据、Owner、截止时间和缓解动作；决定与建议分开 |
| 禁做动作 | 不自动改变优先级、关闭缺陷、承诺发布日期或覆盖路线图 |
| 指标 | 汇总时长、风险遗漏率、决策等待时长、变更可追溯率 |
| 风险 | 版本混用、责任误配、未确认状态被写成决定 |
| 基线 | 记录现有汇总步骤、漏项、等待时间和会后修订 |

### 财务与法务：高后果材料核对

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 大量明细和条款需要定位异常，但最终判断必须由专业人员承担 |
| 角色 | 财务人员、法务人员、业务负责人 |
| 输入 | 获授权的明细、报表、合同版本、规则和专业模板 |
| 当前步骤 | 勾稽或条款抽取、异常定位、版本比较、形成复核清单 |
| 交付物 | 财务勾稽表或条款定位表、异常清单、版本差异和待确认项 |
| 验收 | 金额、日期、公式、条款位置和版本可追溯；专业人员签署结论 |
| 禁做动作 | 不自动记账、付款、修改主数据、给出最终法律意见或签署合同 |
| 指标 | 核对时长、异常检出率、误报率、人工修改量、退回次数 |
| 风险 | 金额或版本错误、权限越界、把提示误当专业结论 |
| 基线 | 保存人工核对时间、已知异常、漏检、误报和复核记录 |

### 内容与市场：有证据的内容流水线

| 字段 | 场景内容 |
|---|---|
| 业务问题 | 选题、素材、审校、发布和复盘分散，事实与品牌风险难控制 |
| 角色 | 内容运营、市场、品牌和设计负责人 |
| 输入 | 已核验来源、选题池、品牌规范、授权素材和渠道要求 |
| 当前步骤 | 研究、选题、起草、设计、事实审校、预览、发布、复盘 |
| 交付物 | 选题证据表、内容草稿、素材清单、发布预览和复盘记录 |
| 验收 | 事实有来源和日期；品牌、版权、链接和渠道格式通过检查 |
| 禁做动作 | 不使用无授权素材，不虚构效果或客户，不未经确认对外发布 |
| 指标 | 制作时长、事实退回率、品牌问题数、发布错误率、复用率 |
| 风险 | 版权、误导表述、敏感信息、过期链接和错误渠道 |
| 基线 | 采集现有周期、审校修改、发布事故和素材复用情况 |

## 案例与证据

五张卡来自现有岗位任务的社区整理，没有使用未经授权的客户名称或效果数字。它们证明的是场景卡如何填写，不证明这些场景在所有组织中优先级相同。

指标必须成对观察效率与质量。例如准备时长下降时，也要检查事实错误、人工修改和风险事件是否上升。没有人工基线或数据口径不同的结果不能直接比较。

## 企业行动

每个岗位只选择一个候选任务：

1. 由业务负责人填写业务问题、交付物、验收和禁做动作。
2. 由使用者记录当前步骤、输入位置和人工基线。
3. 由数据或系统 Owner 核对授权范围和高风险动作。
4. 由内容复核者定义质量指标和退回原因。
5. 把完整场景卡交给第 10 章阶段门评审，本章不自行评分或设阈值。

停止信号包括：场景只能用岗位名称描述；没有可取得的输入；交付物不可验收；禁做动作未明确；指标只记录速度；基线来自不同口径或只保留成功样本。

## 边界与下一步

场景卡不是岗位绩效评价，也不能用 AI 输出替代录用、付款、法律意见、路线图承诺或对外发布决定。组织应按数据敏感度和专业后果增加更严格的规则。

本章负责定义岗位场景，不负责评分和推广阶段门。场景卡完成后，团队仍需建立研究与证据方法，避免把印象写成业务事实。
