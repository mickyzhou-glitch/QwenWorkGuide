# 办公交付：Word、Excel、PPT 与网页

以下案例是工作流设计范式，需在真实权限、数据口径和人工复核下验证。

## 从会议到执行闭环

**输入**：会议转写、会前材料、参会人、项目计划。<br>
**执行**：区分事实、观点、决定和待确认项；提取责任人、截止时间与依赖；先生成纪要和待办草稿，再由负责人确认。<br>
**验收**：决定可回溯到会议证据；待办不使用模糊措辞；无责任人事项不自动创建。

```text
请根据会议转写和会前材料生成评审纪要。先列出需人工确认的人名、数字和日期；
确认后生成结论摘要、已作决定、未决问题、行动项、风险与依赖。
行动项必须有负责人、截止时间、交付物和验收标准；先生成待办草稿，不要直接写入系统。
```

## 经营数据到管理层汇报

**链路**：数据清洗 → 口径核对 → 勾稽校验 → 趋势与结构 → 异常定位 → 结论 → Excel 底稿 → PPT。<br>
**验收**：明细、汇总与 PPT 数字一致；实际、预算、同比和环比不混用；每张图回答一个问题；事实与原因推断分开。

## 行业研究到可引用蓝皮书

**链路**：问题树 → 来源计划 → 多源检索 → 证据卡片 → 交叉核验 → 观点 → Word/PPT。证据卡片至少包含主张、来源日期、原文要点、口径、是否一手来源、冲突与用途。<br>
**验收**：事实有来源，预测有假设，引用可点击，不把新闻转述当官方承诺。

## 合同审阅到协商清单

**链路**：条款抽取 → 风险分类 → 缺失项检查 → 立场对照 → 修改建议 → 协商优先级。<br>
**边界**：AI 可整理材料和提示风险，不替代律师意见；法律结论与重大责任必须由专业人士复核。

## 从需求到可发布网页

**链路**：信息架构 → 低保真结构 → 视觉方案 → 数据交互 → 测试 → 预览 → 人工确认 → 发布。<br>
**验收**：桌面和手机可用；表单校验完善；数据用途明确；不暴露密钥和内部信息；发布前完成内容、隐私和链接检查。
