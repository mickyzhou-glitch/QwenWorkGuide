# 办公交付：文档、数据、汇报与网页

## 30 秒结论

<span id="claim-office-delivery-acceptance-01" data-claim-id="claim-office-delivery-acceptance-01"></span>本书建议：文档、数据、汇报和网页任务都按“输入—处理—产物—验收—风险—人工确认”设计，不能把文件成功生成当成交付通过。

- 文档优先检查事实、结构、版本和可编辑性。
- 数据与汇报必须保留口径、勾稽和结论证据。
- 网页发布及高后果文档使用必须由责任人明确确认。

## 你可能遇到的场景

你可能要把会议材料整理成文档、把一批明细做成表格、把经营数据做成汇报，或把活动内容做成网页。输入例子可以是“会议纪要和模板”“6 月原始表和字段字典”“已确认的经营指标”“内容清单、品牌规范和授权素材”。四类任务都先明确输入，再处理和验收。

## 最后会得到什么

最终交付包按任务类型包含：

1. 文档：可编辑正文、版本说明、待确认清单和来源位置；
2. 表格：可编辑明细、汇总、公式或查询记录、异常清单和口径说明；
3. 汇报：可编辑演示文稿、讲述提纲、数据底稿和待决事项；
4. 网页：可预览页面、源文件、素材清单、测试记录和发布变更清单。

## 照着做

1. 先把输入、处理方式、产物格式、验收条件和人工确认人写成任务卡，原件另存，不在原文件上试跑。
2. 按文档、表格、汇报或网页选择处理步骤：保留来源、版本、公式、链接和必要的修订记录。
3. **中间检查点：**在生成最终文件前，抽查事实、数字、链接、素材授权和格式；有疑问的项进入待确认清单。
4. 生成可编辑或可预览产物，完成自动检查后，由内容 Owner、数据 Owner、业务负责人或发布责任人确认下一动作。

## 做完检查

文档至少抽查 3 个事实和版本；表格至少复算 1 个汇总并核对期间和单位；汇报至少把 1 个图表回溯到底稿；网页至少检查 1 个桌面端、1 个移动端和全部关键链接。任一检查失败就不发布。

## 需要注意

发现版本不明、数字不能复算、素材未授权、合同需要专业判断或网页可能泄露敏感信息时，保留原件和失败产物，停止外发或发布，回到上一稳定版本；改成人工整理或只读分析，由对应专业 Owner 确认后再处理。

## 为什么重要

Office 文件和网页容易制造“已经完成”的视觉错觉：格式完整，但数字无法复算；页面漂亮，但链接失效；合同条款被整理，却被误当成法律结论。业务负责人真正需要的是可使用且可承担后果的产物，而不是一个可下载文件。

统一工作流字段让不同工具和岗位使用同一验收语言。团队可以比较人工与 AI 辅助版本的返工、错误和交付时长，也能在高风险动作前设置清晰的人审边界。

## 方法或模型

### 文档工作流

| 字段 | 规范内容 |
|---|---|
| 输入 | 原始文档、会议材料、模板、术语表、读者和版本范围 |
| 处理 | 识别事实、观点、决定和待确认项；按模板重组；保留修订痕迹 |
| 产物 | 可编辑文档、版本说明、待确认清单和来源位置 |
| 验收 | 结构回答原始任务；事实可查；版本清晰；标题、表格和引用可继续编辑 |
| 风险 | 人名、金额、日期误写；旧版本覆盖；敏感内容外泄；专业结论越界 |
| 人工确认 | 内容复核者批准事实与表达；业务负责人决定外发或进入下一流程 |

会议纪要属于文档工作流：行动项必须有负责人、截止时间、交付物和验收标准。合同属于高后果文档示例；AI 可以定位条款、比较版本和整理协商清单，不能代替法务判断或给出最终法律意见。

### 数据工作流

| 字段 | 规范内容 |
|---|---|
| 输入 | 原始表、字段字典、数据期间、单位、主键、版本和授权范围 |
| 处理 | 保留原件；检查缺失、重复和异常；锁定口径；清洗、计算并勾稽 |
| 产物 | 可编辑明细、汇总、图表、口径说明、公式或查询记录、异常清单 |
| 验收 | 期间与单位明确；口径一致；明细和汇总勾稽；关键结果可复算 |
| 风险 | 补造缺失值、混用期间或单位、主键错配、覆盖原表、越权使用数据 |
| 人工确认 | 数据 Owner 确认口径和范围；内容复核者抽查公式、样本和结论 |

### 汇报工作流

| 字段 | 规范内容 |
|---|---|
| 输入 | 决策问题、受众、数据底稿、事实来源、时间限制和既有模板 |
| 处理 | 先写结论和证据关系；确定讲述顺序；一页一个问题；标注单位与来源 |
| 产物 | 可编辑演示文稿、讲述提纲、数据底稿和待决事项 |
| 验收 | 结论有证据；适合受众；讲述顺序支持决定；图表与底稿一致 |
| 风险 | 用视觉强调替代证据、隐藏不确定性、图表截断、对外承诺未经批准 |
| 人工确认 | 业务负责人确认结论与行动；内容复核者核对数字、来源和表达 |

### 网页工作流

| 字段 | 规范内容 |
|---|---|
| 输入 | 内容清单、信息架构、品牌规范、素材授权、交互需求和发布环境 |
| 处理 | 结构设计、内容与数据绑定、桌面和移动端测试、链接与表单检查 |
| 产物 | 可预览网页、源文件、素材清单、测试记录和发布变更清单 |
| 验收 | 内容正确；链接可达；移动端可用；具备基本可访问性；无敏感信息泄露 |
| 风险 | 未授权素材、表单误收集数据、密钥暴露、失效链接、未经批准公开发布 |
| 人工确认 | 内容 Owner 批准文案与素材；发布责任人确认域名、范围和回退方案 |

完整调用模板集中在 [提示词附录](/bluebook/appendices/prompt-templates)，本章只保留工作流和验收规范。

## 案例与证据

官方产品简介列出 Word、Excel、PPT、网页等产物形态。 [R3](/bluebook/appendices/sources#r3) 产物类型是产品事实；四条工作流、验收项和人审边界属于社区实践，不能据此推断具体任务的一次通过率。

例如经营数据汇报应保留一条完整证据链：原始明细、清洗说明、汇总勾稽、图表数据和演示结论。若演示中的数字无法回到明细或公式，即使 PPT 已生成，也不得通过交付验收。

## 企业行动

从当前返工最多的一类办公产物开始：

1. 用六个字段重写现有流程，补齐缺失的人工确认。
2. 选取真实的通过、退回和边界样本，记录人工基线。
3. 要求 AI 先生成中间产物和校验记录，不直接外发或发布。
4. 由内容复核者按本章验收项逐项退回或通过。
5. 记录返工原因，只固化连续稳定的步骤。

停止信号包括：无法确认输入版本；关键数字不能复算；合同或专业材料缺少持责人员；文件不可编辑；网页存在失效链接或敏感信息；发布对象、域名或回退方式不明确。

## 边界与下一步

本章给出跨岗位通用的办公交付规范，不替代财务、法务、品牌、隐私和无障碍等专业标准。不同组织应在六个字段中追加自己的强制要求，但不要删除来源、验收和人工确认。

通用工作流需要落到具体岗位的业务问题、指标和禁做动作，才能形成可运营的场景组合。
