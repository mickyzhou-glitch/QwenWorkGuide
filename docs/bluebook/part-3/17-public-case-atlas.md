# 公开客户与场景案例图谱

本章从“千问办公 · 职场 AI 三千问”知识库的公开案例库中整理出 **32 个场景案例**，并与本项目已经收录的品胜电子、优克拉两个具名客户案例配合使用。它们覆盖数据研究、电商运营、营销内容、教育与组织协同等方向，可帮助个人和团队从“能做什么”进一步走向“先试哪一个场景”。

::: warning 证据边界
公开案例库提供了案例名称、任务标签、适用角色和部分产物链接，但多数条目没有披露客户名称、实施周期、投入成本或经审计的量化结果。因此，本章将其称为“公开场景案例”，不把它们包装成具名客户背书。产物链接和产品能力可能更新或失效，请以访问时页面为准。
:::

## 先看两个具名客户深度案例

- [品胜电子：竞品调研与产品物料制作](/cases/submissions/pisen-competitive-research-product-materials)：公开材料陈述了竞品调研与物料制作的时间变化，正文同时保留了人工复核和来源边界。
- [优克拉：产品研发与考勤算薪](/cases/submissions/youkela-product-rd-payroll)：公开材料覆盖用户评论分析、研发决策与考勤算薪，量化结果均按“客户陈述、未经独立审计”呈现。

这两类深度案例适合回答“业务为什么要改、工作流如何落地、价值如何衡量”；下面的 32 个场景更适合回答“还有哪些任务值得试、哪些角色可以复用”。

### 复用重点

这组案例的共同链路是：**确定数据口径 → 清洗和勾稽 → 找趋势与异常 → 解释原因 → 形成可交互产物 → 人工复核**。复制案例时，不应只复刻图表样式，还应补齐数据期间、单位、缺失值处理、异常判断规则和结论证据。

### 复用重点

电商场景往往同时涉及平台规则、商品信息、价格、库存和对外发布。更稳妥的做法是把流程拆成“分析/生成草稿”和“确认/发布”两段：AI 可以批量整理和制作，价格变更、商品上下架、素材发布等动作仍应在预览后由责任人确认。

### 复用重点

组织协同场景的价值不只是“生成一个页面”，而是把人员、任务、截止时间、证据和权限串成闭环。涉及候选人、员工评价和人才决策时，应最小化个人信息使用，并明确 AI 只辅助整理，不自动做录用、淘汰或晋升决定。

## 从案例清单变成自己的试点

不要直接问“哪个案例最酷”，而应按以下顺序筛选：

1. 从 32 个场景中选出与本岗位最接近的 3 个。
2. 为每个场景补齐真实输入、责任人、当前耗时、错误成本和验收标准。
3. 优先选择高频、高耗时、输入稳定、可人工复核且失败可逆的任务。
4. 先复刻任务链和验收方式，再决定是否复用示例网页或视觉风格。
5. 连续记录至少 5 次人工基线与 5 次 AI 辅助样本，再判断是否推广。

```text
我想复用案例【案例名称】。我的角色是【角色】，真实输入是【资料与系统】，
当前人工步骤和耗时是【步骤/时间】，最终交付物是【格式】。

请先输出：
1. 案例中可复用的任务链；
2. 不能直接照搬的假设；
3. 所需权限和敏感数据；
4. 人工确认点；
5. 验收标准和基线采集表；
6. 一个只读、可回退的最小试点方案。
不要直接执行发布、写入、发送或删除动作。
```

## 案例引用规则

- **具名客户案例**：只有在存在公开授权材料时使用客户名称；量化结果注明“客户陈述、未经独立审计”。
- **公开场景案例**：引用案例名称、任务标签、角色和公开产物，不补写来源中没有披露的客户名称、成本或效果。
- **内部案例**：先脱敏，再记录输入范围、执行版本、验收结果和失败样本；未经授权不得公开。
- **示例产物**：用于理解交付形态，不等同于生产环境可直接部署的模板；上线前仍需检查内容、隐私、版权和链接。
