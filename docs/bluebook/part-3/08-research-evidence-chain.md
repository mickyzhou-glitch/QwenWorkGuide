# 研究与证据链：从问题树到发布记录

## 30 秒结论

<span id="claim-evidence-card-fields-01" data-claim-id="claim-evidence-card-fields-01"></span>本章将研究证据卡唯一规范定义为九个字段：主张、来源原文、来源类型、日期、统计口径、适用范围、限制、冲突、状态。

<span id="claim-research-question-tree-01" data-claim-id="claim-research-question-tree-01"></span>本书建议：研究先把决策问题拆成可由证据回答的问题树，再检索和写作，避免“搜索到什么就写什么”。

## 你可能遇到的场景

你要查资料形成一份竞品、市场或经营分析结论，但搜索结果很多，来源口径和日期却不一样。输入例子是“要支持的预算决定、截止日期、目标市场、已有官方资料和访谈记录”；先把决定拆成问题树，再开始检索。

## 最后会得到什么

最终产物是一套可发布的研究包，结构为：

1. 问题树和来源计划：每个子问题、优先来源、备选来源和停止条件；
2. 证据卡：主张、来源原文、来源类型、日期、统计口径、适用范围、限制、冲突、状态；
3. 冲突登记：编号、相关卡片、差异、可能原因、处理动作、Owner 和状态；
4. 分层结论：已核验事实、基于证据的推断、建议、待确认问题和发布前复核记录。

## 照着做

1. 先写读者要作的决定，再把它拆成可由证据回答的问题树，并给每个子问题指定来源和停止条件。
2. 采集标题、链接、日期和原文位置，按九字段制作证据卡，不把搜索摘要直接写成结论。
3. **中间检查点：**逐卡核对对象、期间、单位、定义和授权；发现冲突就登记，不用平均数或多数投票掩盖差异。
4. 将事实、推断、建议和待确认问题分层，发布前由未参与撰写的人抽检关键主张、高后果结论和敏感信息。

## 做完检查

随机抽查 3 条关键主张，要求复核人能打开来源、定位原文、复述统计口径和限制；任何一条无法复述，就降低结论强度、补证，或从发布稿移出。

## 需要注意

如果关键数字无原文、来源需要登录却无人负责、不同定义被直接比较，或高后果结论无人复核，保留原始资料和证据卡，停止发布；回到上一稳定版本，改成人工只读分析或并列披露冲突，由数据或专业 Owner 确认后再继续。

## 为什么重要

研究报告最危险的失败不是篇幅不足，而是语言完整却无法复核：转述被写成官方事实，不同口径的数字被直接比较，过期页面支撑当前结论，公开演示被包装成客户效果。

问题树决定需要什么证据，证据卡保存每条主张的边界，冲突登记防止团队用平均或多数投票消除真实差异。它们共同帮助业务负责人判断结论能支持什么决定，以及哪些问题仍需人工确认。

## 方法或模型

先从决定反推问题树：

| 子问题 | 需要的证据 | 优先来源 | 不能直接得出的结论 |
|---|---|---|---|
| 市场是否变化 | 连续期间、规模或增速及完整口径 | 监管、统计、公司披露 | 用单篇报道预测份额 |
| 客户是否有痛点 | 访谈原话、工单或使用数据 | 获授权的一手访谈和内部数据 | 用竞品广告替代客户需求 |
| 方案是否可行 | 产品说明、测试样本、成本和失败记录 | 官方文档、受控试点、原始记录 | 用功能入口推断稳定交付率 |
| 组织是否能采用 | 权限、流程、责任和专业后果 | 组织制度、系统 Owner、专业意见 | 用 AI 摘要代替合规判断 |

一张证据卡只支持一个最小主张，固定字段如下：

| 字段 | 必填内容 | 不合格信号 |
|---|---|---|
| 主张 | 一句可核验、不过度外推的陈述 | 混入评价词或多个结论 |
| 来源原文 | 标题、机构、链接或位置，以及必要原文摘记 | 只有搜索摘要或二次转述 |
| 来源类型 | `official-product`（官方产品）、`regulatory-statistical`（监管统计）、`first-party-disclosure`（一手披露）、`customer-authorized`（客户授权）、`independent-research`（独立研究）、`public-demo`（公开演示）、`internal-pilot`（内部试点）或 `community-framework`（社区框架） | 不说明谁产生了资料 |
| 日期 | 发布、访问和必要的采集日期 | 无法判断是否过期 |
| 统计口径 | 对象、期间、单位、样本、分母和计算方法 | 只有百分比或“显著提升” |
| 适用范围 | 能支持的地域、对象、流程和决定 | 默认外推到全部企业 |
| 限制 | 不能支持什么、缺什么、是否未经独立审计 | 只写结论不写边界 |
| 冲突 | 与其他证据的差异、可能原因和处理动作 | 直接平均不同定义的数字 |
| 状态 | verified、limited、editor-reviewed、pending 或 stale | 用模糊的“可信”代替发布状态 |

来源按原始性和责任边界使用：监管统计、正式披露和获授权一手记录优先支撑事实；完整方法的独立研究可支撑限定范围结论；媒体、合作伙伴材料和专家解读用于补充；搜索摘要、转载和社交媒体只用于发现线索。来源数量不能代替质量和口径一致性。

人机协作采用七步流程：

1. **立题**：明确读者要作的决定、截止时间和不研究的边界。
2. **来源计划**：为每个子问题指定优先来源、备选来源和停止条件。
3. **采集去重**：AI 可整理标题、链接、日期和关键词；人确认原始来源和授权。
4. **制作证据卡**：AI 可抽取结构；人逐卡核对原文、数字、日期和限定条件。
5. **登记冲突**：比较对象、期间、单位、定义和样本，不用平均掩盖差异。
6. **形成论证**：把已核验事实、基于证据的推断、建议和待确认问题分层。
7. **审阅发布**：由未参与撰写的人抽检关键主张，并检查敏感信息、版权和失效状态。

冲突登记至少保留冲突编号、相关卡片、差异内容、可能原因、处理动作、Owner 和当前状态。若无法在截止日前解决，报告应并列披露差异并降低结论强度。

证据卡是研究任务中的工作记录，可以包含未发布线索和仓库外的授权材料；`evidence-ledger.json` 是公开蓝皮书关键主张的发布记录，只保存公开安全且符合发布门的内容。两者职责不同，但来源类型、状态、适用范围和限制必须保持一致。

## 案例与证据

<span id="claim-demo-boundary-01" data-claim-id="claim-demo-boundary-01"></span>本书主张：公开演示只能证明可观察的交付形态，不能据此推导客户身份、实施成本、生产稳定性或业务效果。

公开案例库中的网页、看板和报告链接可以帮助读者理解产物形态。 [R11](/bluebook/appendices/sources#r11) 若没有案例级外部记录 ID、深链或许可范围内的快照，它们只能留作待核验线索，不能进入公开案例数量。

发布前抽检优先覆盖全部关键主张、全部精确数字和全部高后果结论；其他内容按风险抽样。抽检人需要在可接受时间内打开来源、定位原文并复述口径，否则主张应降级、补证或移出发布内容。

## 企业行动

为一个正在进行的研究任务建立证据工作台：

1. 让业务负责人确认决定、问题树和不研究范围。
2. 让研究者按九字段制作证据卡，不直接从搜索结果写结论。
3. 让数据或专业 Owner 复核口径、授权和高后果解释。
4. 建立冲突登记，指定处理人和截止时间。
5. 发布前由独立复核者抽检关键主张，并把公开使用的主张同步到发布台账。

可复制的研究调用方式放在 [提示词附录](/bluebook/appendices/prompt-templates#研究证据链模板)，附录只调用本章字段，不重新定义证据卡。

停止信号包括：关键数字没有原文或口径；来源需要登录却没有资料责任人；不同定义被直接比较；高后果结论无人复核；内部或客户材料没有公开授权；主张状态与正文措辞不一致。

## 边界与下一步

研究整理可以由 AI 加速，但法规解释、投资判断、医学、法律和其他高后果结论必须由具备相应职责或资质的人复核。证据卡完整也不保证结论正确，它只让错误更容易被发现和追责。

本章定义研究证据方法，不决定哪些公开案例可以发布。案例进入蓝皮书还需满足独立的来源定位和公开计数门槛。
