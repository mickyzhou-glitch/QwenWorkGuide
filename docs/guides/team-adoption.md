# 把个人实践带给团队

先选一项重复发生、资料明确、结果容易检查的工作。建议从会议纪要、周报汇总或经营数据整理开始，找到能负责检查结果的人。

## 试点先回答四个问题

| 问题 | 写清楚什么 |
| --- | --- |
| 做什么 | 一个具体场景，以及这轮不处理的范围 |
| 用什么 | 输入材料、账号、目录、技能与连接器 |
| 谁负责 | 使用者、结果检查人、账号或系统管理员 |
| 怎样判断值得用 | 质量、总处理时间、返工量和实际用量 |

个人试用不等于组织部署。企业成员、资源共享、访问策略和用量管理应在对应管理入口配置，不能只靠对话里的口头约定。

## 用同一组样本比较

先记录原来的做法和耗时，再用 AI 执行同一组任务。总耗时应包括准备、等待、检查和返工，不能只算生成过程。对输出打分时关注事实错误、遗漏和可编辑性，而不是只看语言是否流畅。

```text
试点场景：
输入范围与来源：
参与人员与结果检查人：
原流程总耗时：
AI 流程总耗时（含检查和返工）：
错误或遗漏：
单次用量：
是否继续，以及下一步要改什么：
```

## 当前产品变化怎样影响试点

- **用量管理：** 官方 9 月动态介绍了企业版用量看板。可结合实际后台观察成员使用，但消耗高不等于价值高。
- **技能复用：** 个人方法可以整理为技能；共享前先移除私有输入和账号信息，并确认组织审批方式。
- **多人工作台：** 需要共享保存数据时，可按[网页实操](/tasks/team-workspace)先用模拟数据验证权限与保存。
- **安全中心：** 客户端 1.2.0 日志介绍安全状态与操作记录入口；它帮助检查执行过程，不能代替组织对具体动作的授权。

以上产品信息分别见[官方动态](https://learn.qwenwork.cn/whatsnew/)与[客户端日志](https://docs.qwenwork.cn/release-notes/desktop)。本站不给出固定席位、积分、折扣或 POC 商务承诺；采购前查看[官方权益说明](https://docs.qwenwork.cn/benefits)并核对当前合同范围。

## 什么时候适合扩大

当不同使用者能用同样方法处理新样本、错误能够定位、结果有人检查、成本可以接受时，再扩展场景。不要把一次成功演示直接宣布为团队标准。

需要更完整的组织方法，可继续读[场景选择与试点](/bluebook/part-4/10-pilot-roadmap)、[安全与责任](/bluebook/part-4/11-security-governance)和[价值度量](/bluebook/part-4/13-value-measurement)。这些属于社区方法，不是产品强制流程。
