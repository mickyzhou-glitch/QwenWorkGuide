# 把店铺数据变成复盘

**带走什么：** 一份经营复盘、异常明细与下一轮待验证的优化假设。

::: info 先看账号范围
官方 10 月 14 日介绍的电商版面向个人版、切换入口处于邀测，企业版暂未开放；10 月 15 日客户端日志介绍了电商经营模式。两份说明不能推导为所有企业账号已可用。没有入口时，使用已授权导出表也能完成下面的练习。
:::

## 准备材料

选定同一店铺、同一统计期间的流量、成交、退款与投放报表。标明支付金额、退款金额、广告花费、订单数和币种。选择导出表方式时，不需要连接商家后台。

## 操作步骤

1. 先核对每份报表的时间范围和指标定义，确认跨平台数据能否直接比较。
2. 汇总流量、转化、客单价、退款和投放变化，保留原始表。
3. 按商品或渠道找异常；先描述变化，再提出可能原因和补充证据。
4. 给出三项以内的下一步动作，每项写清负责人、观察指标与复查时间。
5. 需要持续读取数据时，再在账号内查看商家连接器，确认支持的工具和授权范围。

## 可复制的指令

```text
根据这组店铺导出报表做一份经营复盘。
先检查统计期间、币种和支付、退款、投放指标的定义；不能比较的项目单列。
输出：核心指标变化、异常商品或渠道、可能原因、待补充证据、三项建议动作。
所有汇总能追溯到原始表，不将相关性当成因果。
ROI 使用我确认的定义，不要混用毛收入、净收入或利润。
本轮只读分析，不调整广告、不修改商品、不操作订单。
```

## 这样检查才算做完

- 退款是否归到正确期间；预售、取消订单是否按一致规则处理。
- 各渠道的统计窗口是否相同，是否重复计算同一笔成交。
- 推广花费与收入的范围是否对应，零花费项目如何展示。
- 每条优化建议有没有明确的验证动作，而不是笼统要求“提高转化”。

商家连接器的存在并不证明全部后台、账号和数据都已接通。先拿一项只读指标与后台对账，通过后再扩大范围。任何投放或商品调整都应单独说明实际动作和预算边界。
