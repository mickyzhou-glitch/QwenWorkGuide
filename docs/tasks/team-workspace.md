# 搭一个团队协作网页

**带走什么：** 一个能预览的工作台原型、字段与角色说明，以及发布检查记录。

千问办公的[网页功能](https://docs.qwenwork.cn/web/pages)支持静态页面与需要保存数据的动态网页。是否需要数据库，应由“刷新后、换设备后是否还要保留数据”决定。多人工作台是这里的应用场景，不等于所有生成网页天然具有正确权限。

## 先做小一点

用一个“活动筹备事项表”作为练习：事项、负责人、计划日期、状态、备注。先录入 5 条虚构记录。不要一开始就连接生产数据或复制整套企业系统。

## 操作步骤

1. 说明使用者、字段、允许的操作，以及哪些人可以看全部事项。
2. 生成页面原型；先检查手机布局、筛选、新增和修改流程。
3. 需要共享保存时，明确提出动态网页与数据持久化要求。
4. 用两名测试用户验证权限，再刷新、重新打开并换设备检查数据。
5. 发布前核对公开范围，保留源文件和数据导出；发布后打开正式链接再测一轮。

## 可复制的指令

```text
为活动筹备做一个小型多人事项工作台，先使用 5 条虚构数据。
字段：事项、负责人、计划日期、状态、备注。
普通成员仅查看和更新自己的事项；管理员可以查看全部并分派任务。
需要数据持久化，刷新和换设备后仍能看到已保存的数据。
先给我页面预览、角色权限表和数据结构，不要直接发布。
完成后列出：功能测试结果、权限实现方式、数据导出方式、发布范围。
如果当前环境做不到某项权限或保存要求，明确说明，不要做成看似可用的按钮。
```

## 发布前逐项验证

| 检查点 | 实际测试 |
| --- | --- |
| 数据持久化 | 新增一条记录，刷新、关闭再打开，记录仍在 |
| 身份隔离 | 用户 A 不能通过改地址或请求参数读取用户 B 的记录 |
| 访问范围 | 未登录者能看到什么，邀请链接是否会意外公开 |
| 失败反馈 | 保存失败有提示，不显示虚假的“成功” |
| 移动端 | 窄屏可读，主要按钮可点，表单不会被遮挡 |
| 恢复 | 已保存源文件与数据导出，知道由谁恢复 |

访问密码保护入口不等同于逐条数据权限。仅在前端隐藏按钮也不是访问控制。

::: info 版本能力要实际核对
截至 2026-10-25，官方“我的网页”说明中的历史版本切换仍标注“即将上线”。本指南不把一键回滚当作已验证恢复方案；先保留源文件和数据副本。删除网页可能同时清空其数据库。
:::
