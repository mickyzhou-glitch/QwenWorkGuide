# 社区案例库

案例库保留从真实工作任务中提炼出的、可阅读和可复用的实践。客户名称、客户结果和量化数字均应按页面中的证据边界阅读，不自动代表其他组织可获得相同结果。

**当前可阅读：2 个具名客户深度案例（4 个业务场景）+ 32 个公开场景线索。**

## 先看可阅读案例与场景

### 品胜电子

- [场景一：竞品调研](./submissions/pisen-competitive-research-product-materials#竞品调研)：将多人手工搜集、整理竞品动态的工作沉淀为结构化调研流程。
- [场景二：产品物料制作](./submissions/pisen-competitive-research-product-materials#产品物料制作)：以产品参数和外观图为输入，生成面向供应商与客户的展示物料草稿。

### 优克拉

- [场景一：产品研发](./submissions/youkela-product-rd-payroll#产品研发)：从大量用户评论中提取痛点、痒点和卖点，形成研发需求报告。
- [场景二：考勤算薪](./submissions/youkela-product-rd-payroll#考勤算薪)：将考勤数据清洗、薪资规则计算和异常复核整理为可重复执行的流程。

### 千问办公公开案例图谱

- [32 个公开场景线索](./submissions/qwenwork-public-case-atlas)：覆盖数据研究、电商与闪购、网站与营销、教育、组织协同和人才管理；它们是待核验公开场景，不是已核验客户案例。
- [蓝皮书公开案例图谱](/bluebook/part-3/09-public-case-atlas)：查看当前证据发布门、候选状态和逐条核验规则。
- [案例来源映射](/bluebook/appendices/case-source-map)：查看 32 个候选条目的原始名称、标签和待补证状态。

## 证据边界与合格案例

**V2.0 证据门状态：当前通过案例级来源定位的公开案例为 <span data-public-case-count="0">0</span>；32 个候选继续保持待核验，在未通过逐条发布门前不作为客户背书或效果证明。**

合格案例不仅描述“用了什么”，还应交代：要解决的问题、谁适用、输入资料、使用能力、执行步骤、最终产物、验收标准和权限安全边界。公开案例还需要案例级外部记录 ID、稳定来源定位和可复核的许可边界；在证据不足时，案例仍可作为研究线索，但不应被传播为已核验客户案例。
